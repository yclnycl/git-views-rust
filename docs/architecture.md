# 应用、Git 与只读预览架构

## 依赖边界

```text
gitviews-app       原生窗口、设计渲染、主题、交互与任务生命周期
       ↓
gitviews-service   仓库读取用例、多仓库列表、状态文件存取
       ↓
gitviews-git       GitBackend、git2 适配与领域数据模型
       ↓
libgit2 / 本地仓库
```

UI 不调用 Git 命令，也不直接持有 `git2::Repository`。Service 不依赖 GPUI。Git 层不读写应用设置，也不保存窗口状态。

## UI

`Workspace` 保存当前仓库快照、分支/工作树信息、文件树、差异、打开的标签、目录展开状态和多仓库列表。`workbench` 将这些数据映射为原生 GPUI 元素，沿用 Pencil 稿的布局、颜色、字体和行高。设计预览与真实仓库模式独立，真实模式不会把示例数据当成 Git 结果。

文件列可按状态分组或按目录展示。Submodule 显示在工作树分区内，带独立图标和初始化/修改状态。双击后创建独立的文件变更上下文，工作区状态和预览读取子模块根，主仓库、分支、提交历史与仓库列表仍保留父仓库上下文。返回主仓库或选择当前工作树可恢复父仓库文件。Service 会校验子模块登记与精确仓库根，避免失效目录向上发现父仓库。主、子监听事件同时使两者预览缓存失效，由同一个后台扫描协调器刷新；请求代际和目标身份共同隔离迟到结果。

所有仓库读取与窗口中的设置文件 IO 在后台任务执行。启动时先同步读取最多64KiB的 TOML，以便配置日志订阅器并初始化主题。仓库和差异请求各有递增标识，过时任务不能覆盖当前选择。切换仓库时清除旧文件标签和内容，刷新时尽量保留仍存在的文件选择。后台保存按次序执行，避免旧快照覆盖较新的列表。

`PreviewPane` 保留 GPUI Kit 的 `EditorState` 和 `DiffState`。源码为只读 Editor，允许选择、复制和查找；Diff 由组件解析和虚拟化展示，支持单双栏、语法高亮与修改导航。解析 patch 在后台执行，源码内容只在变化时应用到 Editor，普通渲染不会反复重置文本或光标。提交历史分页读取，选择提交后读取改动路径，并按需读取该提交与首个父提交的差异；首提交与空树比较。

`FileList` 保留扁平行模型，使用 `uniform_list` 仅构建可见行，覆盖文件树与状态分组。过滤、折叠或数据变化时在 GPUI 后台执行器重建行模型，单任务执行并合并最新请求；共享树、变更与折叠状态，代际拒绝旧结果。切换根目录先清旧行，点击回调再次校验根代次。设计稿渲染只提供框架和元信息，不再预先生成数千代码行或文件元素。

`PreviewDeck` 以仓库根、原始完整路径、暂存标记和完整提交 OID 为标签身份，最多保留8个 `PreviewPane`，按最近使用淘汰非活动控件，估算内容预算32MiB。标签元数据独立保留，最多32项；控件被淘汰后再次激活按需读取。每个控件分别保留 Source/Diff 模式、编辑器选择/滚动和搜索状态。估算包括正文、旧 Editor rope、解析副本和在途 patch，当前控件受保护；此预算不代表进程 RSS 上限。Diff 解析每控件只运行一项，更新合并到最新待处理请求，代际校验拒绝旧结果。

`file_search` 使用当前主仓库或子模块的不可变文件树建立 `SearchIndex`，只读取路径元数据。UI 保存一个索引，用弱树身份判断有效性；无变化扫描沿用原树 `Arc`。100ms 防抖后后台查询，取消令牌、仓库/子模块代际和树身份同时保护结果；打开命中前再次核对上下文，避免同名路径串仓库。搜索结果用虚拟列表，最多200项，显式搜索打开 Source。

`history` 首次读取时冻结 HEAD 的完整 OID，分页沿同一 anchor 遍历，每页100项，最多5,000项/4MiB。HEAD 更新仅提示重新加载，不把新提交插入旧页。哈希/作者/标题筛选仅覆盖已加载项，界面明确显示范围。提交列表、改动文件及提交说明均虚拟化，说明行偏移在后台生成，渲染时只读取可见片段；历史标签按各自提交读取。提交元数据加载状态独立于已打开的预览控件。

当前仓库持有 notify watcher。UI 每100ms取走已防抖的批次，立即失效缓存并安排后台扫描；同时只允许一个扫描，期间新事件合并为下一次扫描，过时结果由仓库代次拒绝。默认10秒定期扫描用于丢失事件或监听不可用时兜底，检查间隔和防抖可由设置调整。扫描比较数据后更新列表，预览内容不变时保留编辑器状态；工作区变化不会重置已加载的提交历史页。

## Service

`RepositoryService<B>` 通过可替换的 `GitBackend` 提供仓库扫描、源码、差异、分页历史、提交详情和提交差异，默认后端为 `Git2Backend`。Service 保持同步接口，由 UI 决定在哪个执行器调度，便于独立测试。

`GitEngineStore` 单独保存设备级 `git-engine.toml`，不改变现有可复制的 `AppSettings`。缺少选择时，Workspace 在后台读取配置后显示强制选择窗口，保存前不会恢复仓库或接受写入。路径检测和版本验证均在后台执行，文件选择器与手动输入共用验证；旧配置损坏时保留原文件，显示路径并提供显式备份重选。Service 克隆共享引擎选择，验证后在写入门锁内先保存再激活，失败时保留当前方案；本地 Git 不可用时返回错误，禁止静默降级。

选择本地 Git 时，Service 将提交、暂存、检出、远端、储藏、分支修改及恢复、合并／变基和工作树写入路由给 `SystemGit`，通过明确参数启动所选程序，不拼接 shell 命令。Git 按自身配置运行 hooks、GPG／SSH 签名及凭据助手。终端输入和提交编辑器关闭，提交消息通过标准输入传递；输出有界，远端错误不展示可能含凭据的原始输出。读取、Diff、历史和搜索仍使用内置实现；冲突文件编辑、修改块及取消暂存保留原有身份校验和索引事务，再调用 Git 索引写入器触发 `post-index-change`。工作树修复／清理登记保留原生所有权检查。内置模式写入先检查无法满足的 hooks 要求，防止悄悄绕过团队策略。

`setup_repository` 与其他写入共用互斥。新建／克隆先在目标父目录分配独占临时目录，成功后重新检查目标不存在或为空，再发布。原生操作取消、普通失败或认证重试只清理本次分配的临时目录，不递归删除用户指定目录。本地 Git 异常终止、取消或超时时，为避免与残留 helper 争用，保留临时目录并显示完整路径，供确认 Git 退出后清理；目标目录不会发布。原生克隆复用绑定协议和主机的 `RemoteAuth`、进度与取消回调；本地 Git 克隆沿用系统认证。UI 单独保存克隆的认证上下文，不依赖已打开仓库；成功后交给现有 catalog 导入和分阶段加载流程。

`RepositoryCatalog` 保存仓库根路径、名称和当前选择。加入前规范化路径，UI 先用 Git 层解析仓库根目录，因此同一仓库的不同子目录不会生成重复项。移除当前条目时选择剩余条目或回到空状态，不删除仓库文件。

`RepositoryCatalogStore` 接收可注入的文件路径，将列表保存为 JSON。不存在的文件视为空列表；无效内容返回错误。写入采用同目录临时文件、刷新与重命名，并拒绝覆盖已损坏的现有文件。Windows 默认路径为 `%APPDATA%\GitViews\repositories.json`；启动参数 `--state-file` 可指定测试或便携状态文件。

`RepositoryService::worktree` 使用与 checkout/remote 相同的共享写入门，拒绝并发请求并失效受影响根的缓存。UI 的工作树管理弹窗冻结当前根和 HEAD，后台执行原生操作后重读登记；请求代次隔离迟到结果，成功保留当前仓库并刷新列表，失败保留表单。移除或移动已存在于仓库列表的条目时，同步更新其登记路径。

`SettingsStore` 将版本化 `AppSettings` 保存为 UTF-8 TOML，默认路径 `%APPDATA%\GitViews\config.toml`，`--config` 可独立指定。字段缺省使用默认值，拒绝未知字段、无效类型、非有限字号和超出范围的预算；64KiB有界读取，同目录临时文件刷新后重命名，拒绝覆盖损坏原文件。`SettingsDialog` 保留独立草稿，所有数值共同校验后才提交；保存期间阻止重复提交，失败保留草稿。重新读取仅做只读后台任务，代际隔离取消后的结果。首次创建配置仅在启动流程执行。

配置保存成功后由 Workspace 统一应用：主题随系统或显式设定；编辑器字号通过 GPUI 全局首选项刷新现有面板；Service 在共享缓存锁中更新预算并立即淘汰，后台持有的 Service 克隆使用相同预算；PreviewDeck 更新自身预算并保护活动面板。主/子模块现有 watcher 均热更新防抖，新建 watcher 回写时再次读取最新配置，扫描循环每次读取当前检查间隔。日志过滤器在启动时创建，日志等级修改下次启动生效，环境变量 `RUST_LOG` 优先。

Service 的预览 LRU 同时限制条目与字节数，默认48项/32MiB，返回共享的 `Arc`。缓存键区分工作区、暂存区与历史修订，检查文件/HEAD/索引元数据；失效代次阻止已失效的后台读取重新填入旧内容，错误不进入缓存。锁只保护缓存元数据，不跨 Git IO 持有。

独立的历史页 LRU 以规范仓库根、完整 anchor、偏移和页大小为键，最多64页/4MiB；工作树变化不失效固定提交页。`SearchIndex` 最多100,000文件/32MiB，拒绝超过16KiB的路径，排除目录、已删除文件、`.git` 和子模块内部。查询最多256字符/1024字节，250ms时间预算，使用有界候选堆保留200项；文件名精确/前缀/包含命中优先，再按路径和模糊匹配排序。取消、索引超限、路径警告和查询超时均显式传播，不能显示为完整的零匹配结果。

## Git

`Git2Backend` 在每次调用时打开仓库，通过 git2/libgit2 直接读取分支、状态、提交、文件树、子模块和差异，并执行获取、仅快进拉取、非强制推送与安全分支检出。不依赖系统 Git 可执行文件。

`worktrees` 使用 libgit2 创建与锁定/解锁/清理登记；移动和修复通过有界 Git 链接读写与同卷 rename 实现，不调用外部 Git。安全层拒绝路径重叠、非 Unicode、symlink/reparse、其他仓库及异常登记；清理/移除只定位同一 common dir 的精确条目。管理持有跨进程租约、当前 HEAD/branch 锁；创建锁目标分支，移除/移动锁目标 index/HEAD/branch，触盘前复验状态和链接。移除先删除已确认干净的工作目录，成功后才清登记；移动链接更新失败尝试回滚，恢复失败明确保留文件。普通失败不强制递归清理创建残留。原生 details 对缺失目录保留条目，锁状态只查 sentinel 元数据，避免解码任意锁原因导致 panic。

`repository_root` 仅打开仓库并解析根，不读取状态或提交历史；`registered_submodule` 只查目标登记及 HEAD/index gitlink，避免切换时扫描整个父树与兄弟子模块。`tree_with_changes` 复用已读取的状态。Service 子模块用例在读取前后执行精确根校验，自身 overview 只读一次，保留初始化和读取中途去初始化的拒绝逻辑；可选取消令牌在登记、overview 和建树边界检查。UI 的40ms选择防抖先合并快速点击，监听器初始化单独在后台执行，不阻塞快照发布。

## 诊断与任务调度

`ui::tasks::spawn` 统一使用 GPUI `BackgroundExecutor` 执行同步 Git/文件系统工作，记录 operation、request_id、priority、queue_ms 与 elapsed_ms。当前子模块、预览、搜索和文件行构造使用 High 优先级，定期扫描与监听器建立使用 Low，其他任务使用默认优先级；此调度不抢占已运行的同步调用。tracing span 只进入同步 worker 范围，不跨 await 持有 guard；UI 回写仍由原请求代际/目标身份校验。源码和 Diff 共用静态 Tree-sitter 语言检测，GPUI Kit 自身的异步语法适配器在大文本时使用后台执行器，无需额外 Tokio 运行时。

`diagnostics` 用 `tracing-subscriber` 安装进程订阅器，默认保留应用 debug 和第三方 info。生产者只格式化并 try_send 到512条有界队列，单条最多64KiB；专用日志 IO 线程负责写入、200ms刷新、5MiB×4轮转和丢弃计数。主函数持有 guard 到 GPUI 退出后刷新并 join；该 IO 线程只处理日志，不承载业务任务。panic hook 记录位置并保留原 hook，应用事件不记录正文、凭据或远端认证载荷。

写操作由 Service 的共享互斥门串行化，UI 在后台执行并阻止并发切仓。每次请求冻结主仓库根、当前分支和 HEAD，在传输/检出前再次验证；扫描代际隔离写操作前的迟到结果，完成后失效缓存并重扫。远端凭据只驻留本次操作内存，按协议、主机和端口绑定，不执行 credential helper，也不绕过证书或 SSH 主机密钥校验。推送只使用明确的当前提交和同名上游 refspec，忽略 mirror、push.default 和自定义批量推送配置。

左侧远程分组以独立的展开集合记录状态，初始折叠；搜索临时显示匹配项，不改变手动展开记录。双击分支行与分支下拉菜单共用 checkout 用例。远程检出创建本地分支并设置上游，已有同名分支仅在上游一致时复用。安全检出会拒绝本地改动、未完成操作、其他工作树占用和忽略文件覆盖，不强制检出或自动储藏。

`RepositorySnapshot` 承载根路径、名称、分支/分离/未出生 HEAD、暂存区和工作区状态、近期提交。`RepositoryDetails` 承载本地/远程分支与工作树。`RepositoryTree` 使用扁平相对路径条目表达目录、普通文件、符号链接和 Submodule，并单独提供子模块元数据。渲染层根据路径组织层次。

文件树合并 Git 索引与未忽略的未跟踪路径，保留已删除文件的状态。不遍历 `.git`、被忽略的构建目录或 Submodule 内部，也不跟随符号链接。子模块数据区分是否已初始化、索引/HEAD/工作区提交及修改状态。

差异接口分别比较 HEAD 与索引、索引与工作区，保留行号、修改块和旧/新文本。文件读取有路径约束与大小限制，二进制或不支持的内容返回可显示的错误。错误保留上下文，不能转换为“工作区干净”。

源码上限8MiB/100,000行、单行16,384字符；Diff 每侧2MiB，同样验证行数与单行长度。字节上限按原始文件/Blob计算，解码及控件会占用额外内存。patch 在 libgit2 print 回调中累计检查16MiB/100,000行预算，达到上限立即停止，避免先生成无界完整 buffer 再拒绝。重命名相似度计算前先读取候选 Blob 大小，超过2MiB则保留新增/删除状态，不加载大候选正文。提交原始对象先校验1MiB上限，再读取作者/说明；每页摘要累计最多4MiB，改动列表最多20,000项和4MiB路径元数据，父提交与分页跳过段的错误同样检查并向上传播。

## 验证

`scripts/performance-baseline.ps1` 和独立 service example 生成固定规模的本地样本，输出耗时分位、缓存统计、进程内存及环境信息；实际窗口测量使用隔离状态、配置和日志。`gitviews::performance` 的 `repository_ready` 表示仓库数据已应用到 UI 模型，并记录加载耗时、文件与变更数量及文件树是否成功；不代表 GPU 首帧或文件列表后台行模型已全部绘制。测量口径与当前数据见 `PERFORMANCE_BASELINE.md`。

Git 层使用真实临时仓库覆盖正常、未出生及分离 HEAD、分支、状态、重命名、冲突、差异、忽略规则、文件树和子模块。Service 测试验证错误传播和列表生命周期。UI 数据映射的测试检查树结构、折叠、过滤及操作绑定；原生窗口还需检查实际显示、仓库切换与异步刷新。

应用的开发依赖开启 Kit `test-support`。`ui::headless` 用 `TestPlatform` 构造生产 `Base Root` 窗口；设置组件测试验证真实事件与对外请求，Workspace 测试通过快捷键打开、输入和保存，验证临时 TOML、主题、全局字号与模态焦点；FileList 测试等待后台行模型完成后点击实际可见行。设计节点及三栏容器使用无生产开销的 `TestSupportExt` 观察，控件通过原生可访问性属性提供值、焦点、禁用状态和边界，校验错误提供 Alert 语义。配置重载重建输入时重新聚焦弹窗，防止旧输入句柄失效导致 Escape 丢失。

模拟事件按应用更新边界刷新延迟订阅，后台工作使用测试调度器而不是线程 sleep；对取消重载使用多个调度种子。Headless 用例随 `cargo test --workspace --locked` 执行，`scripts/test-headless.ps1` 可单独运行。这些用例不启动 native application、不使用真实桌面输入，Windows 的模拟文本/渲染平台不提供 GPU 像素回归证明。

后续写操作继续通过 Service 定义用例并由 Git 层实现，不在渲染回调中操作仓库。
