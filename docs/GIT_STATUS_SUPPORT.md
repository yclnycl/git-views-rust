## XY 状态与列表展示

`X` 表示 HEAD → 暂存区，`Y` 表示暂存区 → 工作区。下表使用 `·` 表示空格；实际 Git 状态中的空格不是一个字母。

| 状态或类型 | 读取与展示 | 内容预览 | 普通写操作 |
| --- | --- | --- | --- |
| `··` 未修改 | 文件树保留已追踪文件，变更分组不列为改动 | 可以查看源码、空差异和历史 | 无需暂存 |
| `M·` / `·M` 修改 | 保留发生改动的一侧，文件名使用修改颜色 | 暂存侧比较 HEAD/index，工作侧比较 index/磁盘 | 普通文件可按文件暂存、取消暂存；合适的文本差异可按代码块操作 |
| `A·` 新增 | 显示在已暂存分组 | 旧内容为空，新内容来自 index | 可取消暂存；提交只取已暂存内容 |
| `·A` intent-to-add | 显示为工作区新增，包含非空和空文件 | index 占位项视为没有已暂存内容，显示工作文件的新增差异 | 按文件或全部暂存会将占位项变成真实暂存文件 |
| `D·` 暂存删除 | HEAD 中存在、index 中不存在，文件树仍保留可选节点 | 显示 HEAD 内容被删除 | 可取消暂存恢复 index 条目，不恢复或覆盖磁盘文件 |
| `·D` 工作区删除 | 文件已不在磁盘，仍可从 index/HEAD 定位 | 显示 index 内容被删除 | 按文件暂存记录删除；不会要求磁盘文件存在 |
| `R·` 暂存重命名 | 使用目标路径；移除仅因旧 HEAD 路径产生的幽灵删除节点 | 从原路径读取旧内容，从目标路径读取 index 内容；补丁含重命名头 | 取消暂存目标时同时恢复原 index 路径，保留磁盘上的移动结果 |
| `C·` 暂存复制 | 在配置 `status.renames=copies` 且有可检测候选时标记复制，保留源文件 | 使用复制源旧内容与目标新内容；补丁含复制头 | 目标文件按普通文件取消暂存，源文件仍独立保留 |
| `T·` / `·T` 类型变化 | 区分于普通修改，使用类型变化颜色 | 可比较普通文件与符号链接目标文本等支持的类型 | 实际路径含符号链接或重解析点时，普通暂存拒绝；可处理的普通文件变化按文件操作 |
| `??` 未追踪 | 逐文件枚举，包括深层目录、特殊名称和空文件 | 新增差异，空文件是有效结果 | 普通文件可暂存；未注册嵌套仓库不会被递归加入父仓 |
| `!!` 已忽略 | 默认状态扫描不枚举；界面具备该状态样式 | 不自动作为普通变更读取 | 不强制添加被忽略的新文件 |
| 无法读取 | 尽量保留状态和局部树节点，并提供读取失败信息 | 无法读取的内容明确报错，不显示伪造内容 | 读写校验失败时拒绝发布 index |

工作区重命名默认保留 Git 的“删除原文件 + 未追踪目标文件”表达，不运行额外的工作区相似度检测。暂存后在有界相似度检测范围内合并为重命名。复制并非仅凭两个文件内容相似就自动认定。

相似度检测的候选文件有大小限制，重命名候选匹配也有数量限制。遇到较大的候选时保留真实的新增/删除记录，不强行加载大对象，也不把小文件预览一起阻塞。当前 `FileChange` 数据记录保留目标路径，旧路径可在重命名/复制补丁头中查看。

### 复合状态

同一个文件的两侧状态不能相互覆盖。按状态分组时，同一文件可能分别出现在“已暂存”和工作区分组；两行对应不同的比较基线。

| 状态 | 含义 | 查看方式 |
| --- | --- | --- |
| `MM` | 暂存过修改，之后又修改 | 已暂存行查看 HEAD → index；工作区行查看 index → 工作文件 |
| `AM` | 暂存新文件，之后又修改 | 分别查看首次暂存内容和后续新增改动 |
| `AD` | 暂存新文件后删除工作文件 | 暂存侧仍能看新增内容，工作区侧显示删除 |
| `MD` | 暂存修改后删除工作文件 | 暂存侧显示修改，工作区侧显示删除 |
| `RM` | 暂存重命名后又修改 | 暂存侧显示原文件 → 重命名目标；工作区侧显示后续修改 |
| `TM` 等类型变化组合 | 一侧类型变化，另一侧内容又变化 | 保留两列；分组按各自比较侧呈现 |
| `D·` 加同路径 `??` | 从 index 删除，但磁盘文件仍在，如 `git rm --cached` | 保留两条状态记录：暂存侧删除、工作区侧未追踪 |

文件树只有一个同路径节点时，上述“暂存删除 + 未追踪”组合呈现为 `D?`。这是树的合并显示，不是新增的 Git porcelain 状态，也不是冲突。后端原始两条状态仍然保留。

## 七种未合并状态

冲突判断使用完整 XY 对，不能只查是否出现字母 `U`。`AA` 和 `DD` 同样是冲突。

| XY | 含义 | 基础 / 当前侧 / 传入侧 |
| --- | --- | --- |
| `DD` | 双方删除 | 存在 / 不存在 / 不存在 |
| `AU` | 当前侧新增 | 不存在 / 存在 / 不存在 |
| `UD` | 传入侧删除 | 存在 / 存在 / 不存在 |
| `UA` | 传入侧新增 | 不存在 / 不存在 / 存在 |
| `DU` | 当前侧删除 | 存在 / 不存在 / 存在 |
| `AA` | 双方新增 | 不存在 / 存在 / 存在 |
| `UU` | 双方修改 | 存在 / 存在 / 存在 |

这些文件使用冲突颜色、冲突分组，且不显示普通暂存/取消暂存按钮。点击变更文件直接打开该文件所属仓库的三方编辑器；不存在的侧明确表示删除。子模块中的同名文件读取子模块自己的 index 和对象库。

普通两方 Diff 不把未合并 index 当成某个完整版本。三方查看、选择版本和编辑结果走专门的冲突接口。保存结果或采用一侧属于显式写操作：校验 HEAD、index 和内容快照，并备份原工作内容后再更新工作文件与 index。

普通文件暂存、全部暂存和普通提交在存在冲突或进行中操作时仍会拒绝。这样不会因一个“全部暂存”动作意外把所有冲突标记为已解决。仓库含 assume-unchanged/skip-worktree 项时，冲突写操作也有明确的保护检查。

应用可读取外部 merge/rebase/cherry-pick/revert 等操作留下的冲突。继续或中止属于另一类仓库操作：仅开放当前实现能够可靠处理的布局。外部变基及其他未支持布局会提示使用原来的 Git 工具继续或中止；这不影响读取可支持的普通文件三侧内容。

## 子模块与 gitlink

父仓库的子模块条目是一个 gitlink，不能把子模块内部文件当作父仓库的普通目录递归处理。

| 情况 | 当前行为 |
| --- | --- |
| 父 HEAD、父 index、子模块 HEAD 不同 | 分别保存记录提交和实际提交，可预览 gitlink 的提交变化 |
| 子模块仅有已追踪文件或 index 改动 | 父仓显示子模块脏状态；gitlink 工作区预览使用 `Subproject commit <id>-dirty` |
| 子模块含未追踪文件 | 同样标记 dirty，不将这些文件加入父仓 index |
| 父仓暂存子模块入口 | 只记录子模块当前 HEAD，不替用户提交子模块内部文件 |
| 查看子模块内部变更、分支或历史 | 切换到子模块自己的仓库范围读取；其本地/远程分支独立于父仓 |
| 子模块未初始化 | 保留条目与记录的提交；分支切换不可用，不向上回退成父仓 |
| 子模块被配置忽略脏状态 | 父状态遵循 Git 配置；文件树额外保留可读取的实际子模块脏状态 |
| 冲突涉及 gitlink、目录或不支持的链接类型 | 不冒充普通文本三方合并；交给明确支持的专门操作或外部 Git 工具 |

父仓库 gitlink 两方预览显示提交信息，不声称展示所有子模块文件的实际文本差异。那些文件需进入对应子模块查看。

## ITA 的读取、暂存与提交

`git add -N` 创建的是“将来准备添加”的 index 占位项，不是已经暂存一个空文件。

- 读取时显示 `·A`，非空和空的 ITA 文件都保留。
- 工作区 Diff 以没有已暂存内容为基线。源码的 `:index` 读取不会把 ITA 伪装成真实暂存版本。
- 按文件暂存或全部暂存后，所选文件变为真实 index 内容，并清除该项 ITA 标记。
- 选择性暂存只转换选中的占位项，其他 ITA 标记保持不变。
- 普通提交排除尚未暂存的 ITA；只有 ITA 而没有真实暂存改动时报告“没有已暂存的改动可提交”。
- 提交时只在私有内存 index 中排除占位项，实际 index 字节和未暂存 ITA 标记保持不变。

## 二进制、编码与预览限制

| 类型 | 状态与历史 | 内容查看 | 暂存方式 |
| --- | --- | --- | --- |
| 普通 UTF-8 文本 | 支持 | 两方 Diff、只读源码；符合条件时三方查看 | 文件级；支持的补丁可按代码块 |
| UTF-8 BOM | 支持 | 源码读取去除 BOM；差异层仍按原始 UTF-8 文本处理 | 文件级保留原始字节 |
| 带 BOM 的 UTF-16LE / UTF-16BE | 支持 | 源码视图可解码；普通文本 Diff 不承诺支持 UTF-16 | 文件级保留原始字节，不能按 UTF-8 补丁处理 |
| 含 NUL、二进制或其他不支持的文本编码 | 支持 | 显示不能用文本视图比较的说明，无十六进制编辑器或通用图片差异 | 满足仓库写入条件的普通文件可整文件暂存；不支持二进制代码块暂存 |
| 超大文件、超长单行、过多行 | 状态仍保留 | 明确报告预览限制，不无限分配内存 | 文件级操作仍需通过读写校验 |

普通两方文本 Diff 的单侧内容上限为 2 MiB，补丁上限为 16 MiB、100,000 行；源码预览上限为 8 MiB、100,000 行、每行 16,384 个字符。空文件有效，不以零字节判定读取失败。

三方编辑使用自己的 8 MiB 侧内容限制。二进制、非 UTF-8 或过大侧内容展示提示，并禁用文本编辑保存；在普通文件类型及其他保护检查通过时，可显式采用某一侧原始字节。符号链接、gitlink 和目录不在普通文件冲突写入范围内。

## ignored 与隐藏 index 标记

| 情况 | 默认行为 |
| --- | --- |
| 未追踪文件命中 `.gitignore` | 不当作普通改动枚举，不自动强制添加 |
| 已追踪文件后来命中 `.gitignore` | 仍显示真实修改；本次 `tracked_now_ignored.log` 已核对 |
| assume-unchanged，`git ls-files -v` 中为小写 `h` | 遵循 Git 的隐藏语义，不为了显示改动而清标记或重写 index |
| skip-worktree，通常标为 `S` | 遵循 Git 的稀疏/隐藏语义，不将磁盘内容自动解释成普通改动 |
| 有隐藏标记时发起普通写操作 | 明确拒绝并提示先检查这些标记；不会悄悄去掉标记或批量覆盖 index |

本次真实仓库中，`assumed_unchanged.txt` 和 `skip_worktree.txt` 在磁盘上有内容变化，但 Git 默认状态隐藏它们；应用保持相同行为。“与 Git 状态完全一致”不表示扫描所有被忽略或被隐藏的磁盘内容。

## 写操作范围与验证

普通 Stage/Unstage/Commit 使用私有 index 和锁校验，完整成功后才发布；普通暂存/取消暂存不会改变工作文件。代码块操作要求补丁与当前基线一致；重命名、复制、权限或类型变化、链接、子模块和二进制等结构性改动应使用支持的整文件操作。

路径必须属于当前仓库，不能跨越父目录、Git 元数据目录、符号链接或重解析点去读取其他位置。Windows 非法名称、设备名、控制字符、危险路径和未注册嵌套仓库会被拒绝。中文、空格、emoji、`#`、`!`、单引号及 `-` 开头的普通合法名称已经覆盖读取验证。

锁冲突、HEAD 变化、index 并发变化、未解决冲突、进行中操作、隐藏 index 标记和签名提交要求等情况各自有保护检查。“支持该状态”不意味着跳过这些检查。应用当前普通提交不实现提交签名，也不执行 Git hook。
